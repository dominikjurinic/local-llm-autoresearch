- e014 crashed purely due to an API issue: `model.features` doesn't exist in this timm version. The fix is to use `forward_features`, the standard timm API across versions.

**Why this matters:**
The current pipeline averages logits of the two crops (tight 1.5x + wide 2.5x) equally. Learned view fusion lets the model weight fine texture vs. context per class — exactly the pore/deposit/stain confusion axis. It's a change in what the model learns, not a knob turn. Expected gain: meaningful improvement on the dominant classification loss (potentially +0.01–0.03+), from an idea never successfully run here.

**Budget check:** The edit keeps everything else identical — same model, same crops, same training loop, same prediction. It only changes how features are extracted and fused during training. No new compute cost.

**Hypothesis:** A learned MLP over [tight feat, wide feat] replaces naive logit averaging; this lets the classifier weight context vs. fine texture per class and resolve pore–deposit–stain confusions that fixed averaging can't. It differs from all prior architecture attempts (bigger/backbone/resolution/more-crop averaging) by learning to combine the two views rather than combining them naively, and it fixes e014's crash by using `forward_features` instead of the nonexistent `.features` attribute.
