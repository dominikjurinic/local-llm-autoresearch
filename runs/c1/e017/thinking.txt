**Let me reconsider the problem from the metric perspective:**

mAP@0.5 depends on the ORDER of predictions within each class. The score is conf × p_class. For a given class c, the predictions are sorted by conf × p_c. 

The key insight: for a box to be a TP for class c, it needs to:
1. Be assigned class c (the row for class c must be among the top-300 for that image)
2. The box must overlap a GT box of class c by IoU > 0.5
3. The score (conf × p_c) determines the order

Since we output all 4 classes per box, the ordering within class c is determined by conf × p_c. The conf is fixed (from the detector). So the ordering is determined by p_c.

For a box that truly is class c: p_c should be high → high score → ranked higher
For a box that truly is class d ≠ c: p_c should be low → low score → ranked lower

The problem is that for confused classes (e.g., deposit and stain), p_deposit and p_stain are both moderately high for both classes.
