Actually, wait. Let me reconsider the problem. Is the classifier really the bottleneck, or is it the scoring/ranking?

Per class: AP depends on the ordering of predictions by score = conf × p[c]. Consider class c. True boxes of class c that have a detector box overlapping (IoU>0.5) — call them "detectable." Our prediction for such a box in class c has score conf × p[c]. If p[c] is high (correct class), it ranks high. False alarms (boxes not overlapping any true box) also get class-c rows with score conf × p[c].

The upper bound (perfect classes) scores overlapping boxes with detector conf (no p[c] factor) and keeps false alarms as class 0. Our system: overlapping boxes scored by conf × p[c] (lower than conf if p[c]<1), false alarms scored by conf × p[c].

So relative to the upper bound, we lose AP because:
1. Wrong-class boxes: an overlapping box predicted as c' instead of c is an FP in c' and a weak/missed TP in c.
2. Ranking: even for correctly-classed boxes, the score conf×p[c] reorders them relative to false alarms.

Both stem from classification quality. So improving the classifier is the main lever. OK.
