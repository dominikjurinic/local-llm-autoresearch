**Let me reconsider the problem from a different angle.**

The classifier is a 4-class softmax. The scores are conf * p[c]. The AP depends on the ORDER of predictions within each class. 

Key realization: For a given eval box, we output 4 rows (one per class), each with score = conf * p[c]. The class with the highest p[c] gets the highest score. So the "chosen class" is argmax p[c], and its score is conf * p[argmax].

Now, for mAP, within class c, we sort all boxes by their score_c = conf * p_c. A box is a hit for class c if it overlaps a true box of class c.

The problem: a box that's actually a stain (true) but we predict as pore (p_pore > p_stain) will:
- contribute to pore's prediction list (as a false positive for pore, since it's not a pore).
- NOT contribute to stain's prediction list at all (because we only output the argmax? No wait, we output ALL 4 classes).

Wait, we output all 4 rows per box. So the box appears in ALL 4 class lists, with different scores. For class c, its score is conf * p_c.

So a stain box that we mispredict as pore:
- In pore's list: score = conf * p_pore (high, since p_pore is argmax). It's a false positive for pore.
- In stain's list: score = conf * p_stain (lower). It's a TRUE positive for stain (it overlaps a stain box). But its score is lower than the pore score.

Hmm, so the box IS in the stain list, just with a lower score. So it's not "lost" — it's just ranked lower in the stain list.

So the "wrong class" cost comes from: the box's stain score is lower than it should be (because p_stain < p_pore), so it's ranked lower in the stain list, hurting stain's AP. And it's ranked high in the pore list, hurting pore's AP (false positive).

So to fix this, we want p_stain to be higher for stain boxes, and p_pore lower. That's exactly what better classification does.
