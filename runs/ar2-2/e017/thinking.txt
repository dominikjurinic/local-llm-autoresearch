Actually, let me think about **the scoring more carefully**. 

The score is `conf * prob[c]`. For a given box, the 4 class scores sum to `conf * sum(prob) = conf`. So the total "mass" per box is proportional to the detector confidence.

In mAP@0.5, for each class, we rank all predictions of that class by score and compute precision-recall. The ranking within a class is what matters.

For class c, the score is `conf * prob[c]`. Two boxes with the same prob[c] but different conf will be ranked by conf. Two boxes with the same conf but different prob[c] will be ranked by prob[c].

The issue is: a false alarm (background box) with high detector conf and moderate prob for some class will score higher than a true detection with lower detector conf and high prob. This is bad for ranking.
