HYPOTHESIS: The classifier is trained on perfect ground-truth crops but must classify noisy detector boxes at test time — a distribution shift (off-center, too-tight, too-loose crops) that likely drives the deposit↔stain and pore confusion. Making detector-proposal training the *primary* signal instead of an add-on, with hard negatives included, targets this shift directly and differs from earlier attempts that only appended proposal boxes to the same GT set.
PLAN: 
1. Build a second training set from dets.csv rows whose split == "train": for each, if it overlaps a crops.csv box by IoU >= 0.5 take that box's cls; otherwise drop it as false alarm (keep them out of classification supervision). 
2. Merge this proposal set with the existing crops.csv GT set, oversampling proposals so they dominate (e.g., 60-70% proposals per batch), keeping the same two-crop pipeline and 160px resolution to avoid slowing the run.
3. Train on the merged set exactly as now; the classifier then learns from the exact box-quality distribution it will see at test time. Check timing stays within 180s by keeping IMG_SIZE=160 and the same two views (TIGHT_CONTEXT, CONTEXT), expecting a ~+0.02 gain since this fixes the main classification error rather than re-ordering scores.
