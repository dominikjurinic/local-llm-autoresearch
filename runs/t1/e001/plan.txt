HYPOTHESIS: The two-crop logit-average classifier is trained only on perfect ground-truth boxes, which mismatches the test-time detector boxes that are imperfectly localized and include background. Retraining with a Faster R-CNN-style second-stage protocol — using IoU-matched positives from the train-split detector boxes plus hard negatives (IoU 0.1-0.5) in a fixed positive/negative ratio — matches the training distribution to test and should directly attack the ~0.12 mAP loss caused by wrong class decisions on overlapping boxes. It differs from the earlier "extra detector boxes" family by introducing negative sampling and IoU-matched labeling, not just appending positives.
PLAN: 1) Change `TRAIN_ON` (no), keep it. Add a function that reads dets.csv train-split boxes, computes IoU with crops.csv boxes, and labels positives (IoU>0.5 overlap with any true box → its class) and hard negatives (any true box with 0.1 < IoU <= 0.5 → class 0 background). 2) Merge these into the training set via a new `BoxDataset` subclass or by concatenating row lists, keeping the two-crop forward pass. 3) Sample positives:negatives in a fixed ratio (e.g. 1:3) per batch by shuffling and trimming, so the classifier learns false-alarm structure too. 4) Keep resolution 160px, two crops, EfficientNet-B0; verify step time: this adds only IoU computation at load (~1s) and no model change, so total stays ~170s within the 180s budget.
