HYPOTHESIS: The two crops are currently fused with a fixed 50/50 logit average, but different defects need different context: pore is small and texture-only (tight crop), while deposit vs stain needs the wider context to separate material from shadow. A learned per-class weight lets the model decide how much to trust the tight view versus the wide view for each class, instead of forcing all classes to weigh both views equally. This targets the dominant error source directly — wrong class assignment on overlapping boxes (0.6288 vs 0.7461 if every box had its correct class) — and is a fundamentally different idea from every prior attempt (bigger backbones, resolution changes, extra crops, or score re-weighting), all of which kept the fixed logit averaging.
PLAN: 1) Add to the model forward path a learnable per-class fusion weight: for each class c, logit_c = w[c] * tight_logit_c + (1 - w[c]) * wide_logit_c, where w is a trainable parameter of shape (4,) initialized at 0.5 and optionally clamped to [0.2, 0.8] via sigmoid to prevent degeneration. 2) Implement this in the training loop: replace `crit((model(xt) + model(xw)) / 2, y)` with `crit(fuse_logits(model(xt), model(xw), w), y)`. 3) At inference, compute the fused logits for both crops and use the resulting per-class probabilities with the same detector-conf multiplication. 4) Add a small number of parameters (4 scalars) — verify the total seconds stay under budget by checking step count per epoch against the log; the change adds negligible compute (<1 s). 5) If the fused weight degenerates on one class, add a small L2 penalty toward 0.5.
