HYPOTHESIS: The dominant error is wrong-class assignment on overlapping boxes (+0.11 mAP potential; pore 62%, deposit 77% vs discontinuity 96%). e008's per-class tight/wide fusion already proved that context weighting matters (+0.005), and the earlier "third very wide (4x) crop" experiment showed that an extra wide view helps specifically the pore class (+0.005). The next step is a 3-crop architecture with per-class soft attention over all three views, so each class can choose its ideal context scale rather than forcing two. This targets the fine-grained pore/stain/d deposit confusions directly and differs from all prior attempts by combining multi-scale crops with learned per-class weighting instead of fixed fusion or resolution changes.
PLAN: A concrete, numbered description of the code changes.
1. Add a third crop context: define CONTEXT = 2.5 (wide), THIRD_CONTEXT = 4.0 (very wide) alongside TIGHT_CONTEXT = 1.5, and change the crop loop from `(TIGHT_CONTEXT, CONTEXT)` to `(TIGHT_CONTEXT, CONTEXT, THIRD_CONTEXT)` in BoxDataset.__getitem__, returning three views [views[0], views[1], views[2]].
2. Replace FusionModel with a learnable per-class attention fusion: output logits for 4 classes where each class's logit = sum over three views of (attention weight per class per view * view logit), with the attention weights as trainable per-class parameters (3 views x 4 classes, softmax-normalized within each class). This keeps one model pass but allows every class to weight tight/wide/verywide differently.
3. Keep training details identical (EfficientNet-B0 pretrained, 160px crops, AdamW LR 1e-3, cosine decay, 180s budget). Because the model now does one forward pass with three views instead of two, estimate: previous ~441 steps; add ~50% per-step compute → ~290 steps expected, still within budget.
4. At inference, use the same fused logits to produce scores = conf * p(c) per class, no change to output format.
