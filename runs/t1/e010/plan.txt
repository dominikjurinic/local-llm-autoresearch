HYPOTHESIS: The dominant error is wrong-class assignment on detector boxes (wrong-class loss ≈ 0.11 mAP; pore 62%, deposit 77% vs discontinuity 96%). Every earlier architecture experiment changed the backbone or input resolution, but none matched the classifier's *training distribution* to the test distribution: at test time this network classifies YOLOv7-tiny proposals (false alarms, misplacements), yet it is trained only on tight ground-truth boxes. Training stage-2 exactly like a two-stage detector — positives sampled from train-split detector boxes by IoU overlap, background sampled from detector false alarms — should raise classifier accuracy where it actually matters and recover a large share of that 0.11 mAP loss. It differs from e009's one change (append IoU>0.5 train dets as extra positives) by adding proper negative sampling and an IoU-graded positive set, matching the test-time box pool rather than just augmenting positives.
PLAN: A concrete, numbered description of the code changes.
1. In `read_csv`/`main`, load all crops.csv rows into `all_crops`. Keep `crops` (GT boxes in TRAIN_ON resolution) as the core positive set.
2. Build `gt_by_image` from all_crops (existing helper from e009). For every train-split det box, compute max IoU vs GT of its image; if >0.5 keep its best-overlapping GT cls as label and mark it a "det-positive". If the det box has no GT overlap at all, mark it a "det-negative" (background) with cls 0 — this is the new ingredient, previously untried.
3. Replace `train_rows = crops + extra_train` with a sampler object: each training iteration draws a batch composed of (a) core GT positives, (b) det-positive boxes, and (c) det-negative boxes, in a fixed ratio (e.g. 1:1:2 or sampled per-iteration from a pre-shuffled list) so the classifier sees real proposal-style inputs with realistic false alarms.
4. Keep everything else identical to e009's train.py (two-crop EfficientNet-B0 with learnable per-class tight/wide fusion, cosine LR, 180s budget). Verify step time stays under ~0.4 s so the run finishes within budget; drop_last=True and a pre-shuffled index list keep iteration fast.
5. Expected gain: recovering even half of the 0.11 mAP wrong-class loss (i.e. +0.03–0.05 mAP) would pass the acceptance margin; the change targets the classifier-accuracy bottleneck directly instead of the ranking/scoring where the current scheme is already near-optimal.
