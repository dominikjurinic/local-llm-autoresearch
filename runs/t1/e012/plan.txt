HYPOTHESIS: The two-crop classifier fuses tight (1.5×) and wide (2.5×) logits with a single per-class weight shared by every box, so the context each box needs is never adapted. Small texture-rich boxes need only the tight crop; deposit-vs-stain boxes need the wide one. A box-level, content-driven weighting — driven by the detector confidence and box quality rather than geometry alone (which failed in e011) — should directly attack the dominant error (wrong class on overlapping boxes: pore 62%, deposit 77% correct vs the +0.11 mAP gap). An ensemble across seeds within a single run is not feasible under budget; instead the gain must come from better fusion, validated against the per-class diagnostic.
PLAN: 1) Add a small "fusion gate" MLP to FusionModel that takes the box quality features (detector conf, log area, aspect ratio — all available on every eval/box row, no extra crop computation). 2) Compute tight/wide logits as before but weight them with per-box per-class weights from the gate: w_box = sigmoid(MLP(features)), then logit = w*lt + (1-w)*lw. 3) At training time, pass the same box features for crops.csv boxes (using their conf if available, else a fixed value or derived quality). 4) Keep all other settings identical (two-crop EfficientNet-B0, 160px, cosine LR) so runtime stays ~160s. The gate has ~300 params, negligible compute cost at inference.
