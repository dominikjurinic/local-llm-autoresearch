HYPOTHESIS: The dominant loss is class confusion on true defects (pore 63% right, deposit 77% right, both often read as "stain"). I hypothesise this is a data-quality problem, not a capacity problem: the model learns pore/deposit/stain from clean ground-truth boxes but must classify stage-1 detector boxes whose offsets/sizes differ. The previous mix of GT and detector boxes in one pass gave only +0.004. A two-phase approach — train on clean GT boxes first, then fine-tune on detector boxes with IoU-based labels that also hard-sample the confusing false alarms — directly adapts the classifier to the detector distribution and should close most of the ~0.10 mAP gap. This differs from earlier runs by training the two distributions sequentially rather than mixing them in one pass.
PLAN: 1) Keep the e009 architecture (4-scale pyramid, efficientnet_b0, 160px, SGD with cosine schedule). 2) Add a dataset flag and a second DataLoader that uses dets.csv 'train' rows as training targets: for each train split detector box, find crops.csv boxes overlapping it by IoU > 0.5; if found, label the row with that box's class (as before), else keep it as a false alarm and give it an extra negative class so the model learns to reject it. 3) Training loop: first run the GT training phase for K steps (K = number of steps in one epoch on GT boxes, ~94 at batch 64), then switch to the detector-box phase for the remaining budget steps with a lower LR (e.g., 3e-4) and cosine continuation. 4) Keep the same inference code and output contract. Budget arithmetic: e009 takes ~157 steps in 168 s total; add one extra epoch worth of steps (~94) plus small overhead, so roughly +50 s — still under 180 s if we start training earlier by reducing the image-loading reserve to 60 s.
