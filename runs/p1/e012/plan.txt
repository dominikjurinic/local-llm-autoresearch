HYPOTHESIS: The dominant remaining loss (~0.10 mAP) is class confusion on true defects, especially pore→stain (35% of pores) and deposit→stain (20% of deposits). I hypothesise this happens because the stage-1 detector boxes are systematically offset from the true defect centres — training/ test crops are built from the same box coordinates, so at test time a "pore" box may contain mostly normal weld surface while its true centre lies elsewhere. This makes a tight 160px crop of pure texture useless. The fix: use *hard-aligned* crops that include an image-derived estimate of the defect centre (e.g. re-centre the crop on the brightest/darkest point inside the box, or on the point of maximal gradient), so training and test both show a well-centered defect with its rim/context. This differs from earlier "offset" experiments because it changes what the model *sees* (centre-anchored texture) rather than just resampling scales.
PLAN: 1. In BoxDataset.__getitem__, compute an estimated centre for each box: inside r, find the pixel where |gradient| is maximal across RGB channels (max over axes), use that as crop centre; keep the same side computation and jitter. 2. Also add a second training-only augmentation: randomly jitter the crop centre by up to ±0.15*side so the model learns offset-invariant classification (this mimics test-time offsets without needing them at inference). 3. Keep everything else (4-scale pyramid, EfficientNet-B0, 160px, loss, LR, schedule) identical. Expected gain +0.02-0.05 mAP if the centre-misalignment theory is correct. Time budget: same crop pipeline, no extra models; prediction time unchanged (~13s); training steps per second unchanged (same batch/size).
