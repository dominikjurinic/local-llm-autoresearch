HYPOTHESIS: The dominant remaining loss (~0.10 mAP) is class confusion on true defects, especially pore→stain (35% of pores) and deposit→stain (20% of deposits). I hypothesise this happens because the stage-1 detector boxes are systematically offset from the true defect centres — training/test crops are built from the same box coordinates, so at test time a "pore" box may contain mostly normal weld surface while its true centre lies elsewhere. The fix: use *hard-aligned* crops re-centred on an image-derived estimate of the defect centre (the pixel of maximal RGB gradient magnitude inside the box), so training and test both show a well-centred defect with its rim/context, plus a training-only ±0.15·side centre jitter for offset invariance. This differs from earlier "offset"/scale experiments because it changes what the model *sees* (centre-anchored texture) rather than resampling scales. Fix vs. plan: the gradient-max centre is computed once per box and reused for all 4 scales (cheaper, and the scales already differ by side); the extra ±0.15 jitter is applied to the shared centre, and I bumped RESERVE_S 85→100 to keep a prediction-time margin for the added per-box gradient cost.

def estimate_centre(img, r):
    """Image-derived defect centre: pixel of maximal RGB gradient magnitude inside the box."""
    h, w = img.shape[:2]
    x0, y0 = max(0, int(r["x1"])), max(0, int(r["y1"]))
    x1, y1 = min(w, int(r["x2"])), min(h, int(r["y2"]))
    if x1 - x0 < 2 or y1 - y0 < 2:  # too small to take a gradient: fall back to box centre
        return (r["x1"] + r["x2"]) / 2.0, (r["y1"] + r["y2"]) / 2.0
    region = img[y0:y1, x0:x1].astype(np.float32)
    gx = np.zeros_like(region)
    gy = np.zeros_like(region)
    gx[:, 1:-1] = (region[:, 2:] - region[:, :-2]) * 0.5
    gy[1:-1, :] = (region[2:, :] - region[:-2, :]) * 0.5
    mag = np.sqrt((gx * gx).sum(-1) + (gy * gy).sum(-1))
    iy, ix = np.unravel_index(int(np.argmax(mag)), mag.shape)
    return x0 + ix, y0 + iy
