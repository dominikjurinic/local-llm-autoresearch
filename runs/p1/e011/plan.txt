HYPOTHESIS: The dominant error is pore (63%) and deposit (77%) misclassified as stain, i.e. a texture-level discrimination problem that 160px crops + efficientnet_b0 cannot solve. Give the classifier a dedicated high-resolution stream at full image resolution so pores — which fill only a few pixels in a tight crop — carry enough fine texture, while the existing pyramid keeps the wide context. This is a "two-branch" change to what the model sees rather than a loss or sampling tweak.
PLAN: Add a second branch to MultiScaleClassifier that crops the box at full-image resolution (context scale ≈ 1x of the image) and passes it through a separate projection head before merging. Concretely: in BoxDataset, build an extra view using context=1.0 (the box at original image size) with MIN_CROP set to max(box_side, 64) so small defects keep meaningful pixel size; resize this crop to 256x256 instead of 160. In the model, add a second backbone branch: project the high-res view to proj_dim via Conv2d and pool to a feature vector, then concat with the pyramid features (pyramid output stays unchanged), doubling hidden to keep capacity. Train jointly on the merged head. Budget arithmetic: one extra crop adds ~30% data-load cost; the 256px branch costs ~4x the forward time of one 160px view, but only for the first epoch of steps — estimate total seconds stays under budget by keeping SCALES at 4 and batch size 64.
