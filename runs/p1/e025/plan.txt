HYPOTHESIS: The current 0.6359 loses ~0.10 mAP almost entirely to pore→stain and deposit→stain confusion — the model sees a crop, not the defect. The hypothesis is that stage-1 detector boxes are frequently offset from the true defect center so a crop around the box center often contains no defect at all (only weld background), so the classifier is literally classifying the wrong thing. Rather than only widening crops (e009's pyramid, already tried), I will add an explicit *center-regression* head that re-centers every crop on the detected defect before classification: 1) jointly train a small CNN to predict a per-box offset (dx, dy) in normalized box coordinates, supervised by IoU-maximizing alignment between the GT box and the stage-1 detector box on training boxes; 2) at inference, re-crop each eval box using its predicted offset, then feed the re-centered crops through the existing pyramid. This targets the "classifier sees background" part of the error instead of more scales/texture tricks.
PLAN: 
1. Add to BoxDataset.__getitem__ an optional regression target: for training boxes in crops.csv compute (dx, dy) = center(GT_box) - center(detector_box), where the detector box comes from dets.csv matched to the GT box by highest IoU over train-split rows of the same image. Store it as a 2-vector per row and return it.
2. Change MultiScaleClassifier to accept a 'regress' flag: append two extra MLP heads (a shared hidden layer, then one linear of size 2 each) on top of the fused pyramid vector; predict offsets in normalized box coordinates with a smooth L1 or MSE loss (clip to |offset| < 0.5).
3. Joint loss: total = cross_entropy + alpha * l1_offset, where alpha ~ 1.0 scales offset error comparable to classification loss. Train on the training boxes only; eval boxes get zero offset and are classified with the re-centered pyramid features (crop at box center first, then apply offsets computed from a simple fallback that keeps the original crop).
4. Keep everything else: same backbone, 4-scale pyramid, same budget — add one small head, ~10% more compute per step. Verify timing within 180s with seed 0 before running full seeds.
